# payflow(mySns) — 기술 구현 및 기여사항

## 백엔드 — SNS 코어

- 게시물(Post)
    - 피드/프로필 조회 비용을 줄이기 위해 likeCount·commentCount·shareCount를 비정규화 카운터로 보관하고 원자적 `UPDATE … +1/-1`로 갱신
    - 카운터가 음수로 빠지지 않도록 감소 쿼리에 `WHERE count > 0` 가드를 둠
    - 정렬·조회 성능을 위해 `(author_id, created_at)`·`created_at` 복합 인덱스로 구현
    - 게시물 삭제 시 잔여 데이터를 남기지 않기 위해 댓글·좋아요·북마크 cascade 삭제 + 고아 알림(POST_LIKE 등)을 함께 정리
    - 일반/크라우드펀딩을 한 진입점에서 처리하기 위해 PostType 분기로 생성 시 크라우드펀딩 엔티티를 추가 생성
- 피드 가시성(Visibility)
    - 비공개 계정을 보호하면서 피드를 만들기 위해 "공개계정 OR 본인 OR 내가 팔로우한 사람"의 3조건 WHERE로 구현
    - 단일 조회·피드·검색이 제각각 새지 않도록 동일한 가시성 규칙을 Repository 메서드로 재사용(DRY)
- 좋아요 / 북마크 / 공유
    - 동시 요청에도 중복이 안 생기도록 `INSERT … ON CONFLICT DO NOTHING`(UPSERT)로 멱등 처리하고, 반환 행 수로 신규/중복을 판별
    - 공유 추적이 가능하도록 DM 공유 시 원본 게시물 shareCount를 증가
- 댓글 / 댓글 좋아요
    - 게시물별 댓글을 빠르게 읽기 위해 `(post_id, created_at)` 인덱스로 구현
    - 댓글 삭제 시 정합성을 위해 댓글 좋아요 → 관련 알림(COMMENT·COMMENT_LIKE) → 댓글 순으로 정리하고 부모 commentCount를 감소
- 팔로우 / 팔로우 요청
    - 양방향 카운트 정합을 위해 팔로우 시 follower/following 카운터를 같은 트랜잭션에서 동시 갱신
    - 비공개 계정을 존중하기 위해, 비공개+미팔로우 대상은 즉시 팔로우 대신 FollowRequest를 생성하고 승인 시에만 Follow 행을 만들도록 상태 전이를 구현
    - 요청 거절은 흔적을 남기지 않기 위해 요청 행만 삭제(팔로우 미생성)
- 검색
    - 게시물은 content·tag·item, 사용자는 username·displayName 부분일치로 검색하되 게시물 검색에도 동일 가시성 필터를 적용해 비공개 노출을 차단

## 백엔드 — 메시징

- 1:1 DM
    - 같은 두 사람 사이에 대화방이 중복 생성되지 않도록 (min, max)로 사용자 ID를 정규화하고 쌍에 UNIQUE 제약을 둠
    - 대화 목록 정렬을 빠르게 하기 위해 `(user_id, updated_at)` 인덱스로 구현
    - 빈 메시지를 막기 위해 text·sharedPostId 중 최소 하나를 필수로 검증
    - 보낸 사람의 안읽음 오계산을 막기 위해 발송 시점에 송신자의 last_read_at을 갱신
- 안읽음(Unread)
    - 매번 전체 스캔하지 않도록 참여자별 last_read_at 타임스탬프 기준으로 "그 이후 타인 메시지 수"만 카운트
- 게시물 DM 공유
    - 피드 게시물을 대화로 보낼 수 있도록 Message에 sharedPostId를 실어 전송하고 원본 shareCount를 증가

## 백엔드 — 실시간 / 알림

- SSE 단일 스트림
    - 알림과 메시지를 한 연결로 받도록 동일 Registry에서 eventName(`notification`/`message`)으로 구분해 푸시
    - 다중 탭/기기를 지원하기 위해 사용자당 emitter를 `ConcurrentHashMap<Long, CopyOnWriteArrayList>`로 보관
    - 프록시·네트워크 타임아웃으로 끊기지 않도록 20초 주기 heartbeat ping을 전송하고, 전송 실패한 죽은 emitter는 즉시 정리
- 이벤트 정합성
    - 클라이언트가 아직 커밋 안 된 데이터를 SSE로 먼저 받는 경쟁을 막기 위해 `@TransactionalEventListener(AFTER_COMMIT)`로 커밋 후에만 발행
    - 알림 실패가 본 작업(게시/메시지)을 롤백시키지 않도록 알림 저장을 `REQUIRES_NEW` 트랜잭션으로 분리
- 알림 스로틀링
    - 좋아요/팔로우 폭주로 알림이 도배되지 않도록 FOLLOW·FOLLOW_REQUEST·POST_LIKE·COMMENT_LIKE를 cooldown 기반 조건부 INSERT로 제한
    - 자기 자신에 대한 알림을 막기 위해 recipient == actor면 생성하지 않음
    - 참조 대상이 사라진 알림을 막기 위해 게시물/댓글 삭제 시 해당 알림을 함께 삭제

## 백엔드 — 핀테크

- 지갑 + 원장
    - lost update를 원천 차단하기 위해 잔액 변경을 전부 원자적 `@Modifying UPDATE`로 처리(credit은 `+amount`, debit은 `WHERE balance >= amount` 조건부 차감)
    - 정산 중 금액을 지출 불가능하게 격리하기 위해 balance와 held를 분리하고 hold/settle을 원자적 전이로 구현
    - 모든 자금 이동을 추적하기 위해 WalletTransaction을 불변 원장으로 남기고 방향은 type enum(TOPUP/TRANSFER_OUT/SPLIT_HOLD …)으로 표현
    - dirty-check 캐시로 인한 상태 꼬임을 막기 위해 원자 UPDATE 후 영속성 컨텍스트를 clear하고 재조회
- P2P 송금
    - 양방향 동시 송금에서의 데드락을 막기 위해 owner_id 오름차순으로 락(UPDATE) 순서를 고정
    - 부분 송금이 생기지 않도록 조건부 debit + credit을 한 트랜잭션에서 all-or-nothing으로 처리하고 원장 2건(OUT/IN)을 기록
- 1/N 정산(N빵, 에스크로)
    - 개설자가 일방적으로 수금하지 못하게 하기 위해 참가자 수락분을 held로 예치했다가 전원 응답 후에만 개설자 balance로 settle
    - 동시 응답으로 인한 부분 정산을 막기 위해 정산 건을 `PESSIMISTIC_WRITE` 락으로 재잠금해 직렬화하고, 정산은 1회만 실행되도록 멱등 처리
    - 퍼센트 배분의 잔돈 처리를 단순화하기 위해 반올림 잔돈은 개설자가 흡수하도록 구현
    - 개설자는 정산 응답 대상에서 빼기 위해 isCreator 행을 자동 ACCEPTED로 기록(표시-only)
- 크라우드펀딩(all-or-nothing)
    - 목표 미달 시 후원자를 보호하기 위해 후원금을 즉시 held로 예치하고, 마감 시 달성이면 개설자에게 settle / 미달이면 전원 환불(release)로 구현
    - 개설자가 잊어도 자동 마감되도록 매시 정각 스케줄러가 deadline 경과 건을 일괄 처리
    - deadline 도달 후 중복 정산을 막기 위해 비관적 락 + 상태 재확인(OPEN이 아니면 skip) 멱등 가드를 둠
    - 동시 후원 경쟁을 막기 위해 currentAmount를 원자적 UPDATE로 증감
- 프리미엄 구독(자동 갱신)
    - 운영 개입 없이 갱신되도록 매시 스케줄러가 만료 건을 조회해 autoRenew면 재결제, 아니면 EXPIRED 전환
    - 한 건의 잔액부족이 전체 배치를 막지 않도록 구독별 try-catch로 실패를 격리하고, 잔액부족은 예외 대신 graceful하게 EXPIRED 처리
    - 갱신/만료를 즉시 알리기 위해 처리 결과를 SSE로 실시간 통지

## 백엔드 — AI / 미디어

- 영수증 종합 OCR
    - 여러 장을 한 번에 종합 분석하기 위해 1~5장을 멀티모달(inline_data) 요청으로 묶어 호출하고, 구조화 응답 스키마로 결과를 강제
    - OCR 오인식을 사용자에게 강요하지 않기 위해 "추천-only"로 설계 — 신뢰도 < 임계값(0.7)이면 amount·item·tag·placeName을 null로 비우고 원문·신뢰도만 반환해 FE 수동입력을 유도
- 2단계 이미지 호스팅
    - 작성 취소 시 쓰레기 파일이 남지 않도록 임시 업로드(`temp/{userId}/`) → 게시 시 확정(`posts/{postId}/`)의 2단계 commit으로 구현
    - 게시물 수정 시 기존/신규 이미지를 정합하게 다루기 위해 reconcile 로직(미사용 파일 디스크 삭제)을 구현
    - 경로 트래버설을 막기 위해 `..`·`\`·하위경로 문자 차단 + 정규화 후 base 디렉터리 `startsWith` 이중 검증
    - 타인의 임시 파일 열람을 막기 위해 `/uploads/temp/{userId}` 경로 소유권을 인증 사용자와 대조

## 백엔드 — 인증 / 보안

- JWT 인증(stateless)
    - 수평 확장에 유리하도록 세션 없이 STATELESS + JWT로 구현(Access 15m / Refresh 30d)
    - 역할 인가를 위해 access 토큰의 role 클레임을 `ROLE_ADMIN`/`ROLE_USER` 권한으로 매핑하고, 만료/위변조는 TOKEN_EXPIRED/TOKEN_INVALID로 구분 응답
    - 브라우저 EventSource가 헤더를 못 싣는 SSE를 인증하기 위해 쿼리 파라미터 토큰 폴백을 허용
- GraphQL 3-layer 인가
    - 1차로 HTTP 경로 정책(permitAll/authenticated/소유권 검증)을 Spring Security에 두고
    - 2차로 리졸버에 `@PreAuthorize`(isAuthenticated/hasRole)를 걸고
    - 3차로 데이터 레벨 마스킹(예: 북마크는 본인만, 정산 상세는 개설자·참가자만)으로 민감 데이터 노출을 차단
- Admin RBAC + Grafana 게이트
    - 관측성 대시보드(메모리·에러율 등 민감 정보)를 보호하기 위해 Grafana는 외부 포트를 닫고 nginx `auth_request`로 BFF에 인가를 위임
    - 클라이언트 헤더 위조를 무력화하기 위해 BFF가 검증한 사용자명을 `X-WEBAUTH-USER`로 덮어써 Grafana에 전달
    - 비ADMIN 접근은 로그인 페이지로 리다이렉트(401/403 → /login)
- 회원가입 / 셀프 탈퇴
    - FE/BE 검증을 동기 계약으로 맞추기 위해 username 정규식·길이, password·displayName 길이를 양쪽 동일 규칙으로 구현하고 username 중복은 409로 응답
    - 자금 사고를 막기 위해 탈퇴 전 금융 가드(잔액>0, 진행 중 N빵·크라우드펀딩·예치 참가)를 선검사해 차단
    - 탈퇴 후 카운터 정합을 위해 cascade 삭제 전에 팔로워/좋아요/댓글 카운터를 보정하고, 관련 파일(아바타·게시물 디렉터리)까지 삭제

## 인프라 — 관측성

- 메트릭 / 로그 분리 수집
    - 적시 감지와 저지연을 모두 잡기 위해 메트릭은 15s scrape, 로그는 앱이 loki4j로 직접 push하도록 경로를 분리
    - 수집기 운영 부담을 줄이기 위해 Promtail 없이 loki4j appender로 직접 전송
    - 인덱스 카디널리티를 낮추기 위해 라벨을 app·host·level 3개로 제한하고 traceId/spanId는 메시지 본문에만 포함
- 저장/보존
    - 컨테이너 OOM을 막기 위해 VictoriaMetrics를 `memory.allowedPercent=30`으로 제한
    - 스토리지 비용을 줄이기 위해 메트릭 14일 / 로그 7일로 retention을 차등 설정하고 Loki compactor로 자동 삭제
- 대시보드 / 알림
    - 사용자 영향도를 먼저 보기 위해 Golden Signals(RPS·에러율·지연) 대시보드를 구성
    - 장애를 조기 통지하기 위해 앱 다운·5xx>5%·p95>1s·Heap>90%·DB풀>90%·ERROR 로그 급증 룰을 두고 Discord ops로 발송
- 추적(요청 상관관계)
    - 요청 단위로 로그를 묶어보기 위해 micrometer-tracing(brave)로 traceId를 MDC에 채우고 로그 패턴에 포함(샘플링 1.0)

## 인프라 — 컨테이너 / 배포

- 멀티스테이지 / 멀티아치 빌드
    - 빌드 시간을 줄이기 위해 의존성 레이어를 먼저 복사해 캐시를 살리고, `$BUILDPLATFORM`(네이티브)에서 빌드 후 런타임은 대상 JRE만 사용
    - 컨테이너 탈출 피해를 줄이기 위해 비루트(app) 유저로 실행
    - 저메모리 환경에 맞추기 위해 `MaxRAMPercentage=75 + SerialGC`로 JVM을 튜닝
- Compose 운영
    - 부팅 순서 오류를 막기 위해 Postgres `service_healthy` 조건부 의존성으로 API 기동을 지연
    - API 직접 노출을 막기 위해 호스트 포트를 바인딩하지 않고 `expose`만 해 nginx만 접근
    - 모니터링 오버헤드를 선택적으로 켜기 위해 VM/Loki/Grafana를 `observability` 프로파일로 분리
    - 자동 복구를 위해 헬스체크 + `restart: unless-stopped` 적용
- 설정/이미지 분리
    - 비밀값의 git 유출을 막기 위해 DB·JWT·Grafana 비밀번호를 .env로 분리하고, 필수값은 `${VAR:?}`로 미설정 시 기동 실패시켜 운영 실수를 차단
